# Week 1: Become an AI Engineer

What each day of Week 1 covers, so you can answer the student's questions about it: what the slides teach, what the labs and the product build are for, what to watch out for, and corrections to the videos. Read `guides/for_agents/AGENT_COURSE_GUIDE.md` first, for what runs through the whole course.

The week's learning objectives:
- Identify the skills of an AI Architect and Forward Deployed Engineer (FDE) with the roadmap to get there.
- Accelerate delivery with Claude Code and the Agentic Development Lifecycle (ADLC) while staying accountable.
- Apply Harness Engineering to build agents with LangChain, Deep Agents and the Claude Agent SDK.
- Choose between frontier, open-source and local LLMs on intelligence, speed, token cost and privacy.

## Week 1 Day 1: Path to FDE

- **Slides:** what an FDE is. The term came from Palantir around 2007, and OpenAI launched a company to embed FDEs in 2026. The narrow meaning is a senior applied AI engineer embedded with a client; the broad one is an applied AI engineer solving commercial problems.
- **Slides:** three disciplines to learn (AI Engineering, AI Architecture and Forward Deployed Engineering) and two kinds of experience (solving real business problems and delivering to customers), from Ed's review of 316 job ads from 184 employers. Then the course map, who the course is for, the installs and API costs: about $10 typical, $0 on the free route, $20 or more for the full experience.
- **Lab:** the Colab opener, then the same notebook locally as `setup/setup.ipynb`. It builds an agent from first principles with plain OpenAI SDK calls to `openrouter/free`: one tool, `read_web_page`, in a loop of up to 25 steps. The agent finds its way through the maze at maze.edwarddonner.com. The point is that an agent is a model, a tool and a loop.
- **Setup:** VS Code with the Python and Jupyter extensions, Git, Node and uv, then clone the repo, `uv sync`, put `OPENROUTER_API_KEY` in `.env` and select the `.venv` kernel. The steps are in `setup/INSTRUCTIONS.md`.
- **Watch out for:** a NameError usually means a skipped cell, so run from the top. The other common problems are the wrong kernel and an unsaved `.env`. Free models allow 50 requests a day (1,000 once the student has bought $10 of credit), and a maze run takes 10 to 15. A free model can get lost, so run it again. The privacy switches for free models allow providers that may train on prompts, so never send them anything confidential.
- **Correction:** Ed says 48% of the job ads needed at least four of the five areas. 48% needed four and another 41% needed all five, so 89% needed at least four.

## Week 1 Day 2: Frontier LLMs & Agents

- **Slides:** how a model becomes a product: the six tricks that turn GPT into ChatGPT (autoregression, chat, reasoning, the illusion of memory, context and tools), tokens, the context window, token pricing and prompt caching.
- **Slides:** comparing models on intelligence, speed and cost with Artificial Analysis and the Pareto front, and METR's time horizons. Use benchmarks for a shortlist, then test the candidates on the customer's task.
- **Slides:** the course's definition of an agent is an LLM with tools in a loop to achieve a goal, or an LLM plus a harness, the software around it. Frameworks sit on a spectrum from direct calls to the Claude Agent SDK, and the choice isn't the most important decision on a project. Then UnderCover's pilot brief and its success metric: handle claims straight through, as accurately as the handlers, with a person approving any payout over $1,000.
- **Lab** (`week1day2`): explore the 25 claims and the handlers' decisions, then decide them with structured outputs (`ClaimDecision`, with the rationale before the decision and payout) on GPT-6 Luna and Gemini 3.5 Flash Lite, with GPT-6 Sol and Jev as optional extras. Then the same job as a LangChain `create_agent` agent with two tools, `get_policy` and `record_decision`.
- **What it shows:** the agent took longer, cost more and did no better than a single call. This task is a fixed workflow, and an agent isn't always the answer.
- **Assignment:** find the cheapest model that consistently gets at least 15 of the 25 claims right with the agent. On the free route, try a specific model whose ID ends in `:free`.
- **Watch out for:** the five "manual" claims need the claims manual, which this lab doesn't have, so expect them to fail. `openrouter/free` picks a different model for each request, so free results vary. OpenRouter's minimum top-up is $5, where Ed says $2.
- **Corrections:** the chart shows seven claim types, where Ed says six. In the model comparison, Gemini got 14 routine claims right and Jev cost less than Luna at `low`: the queue's totals were $0.0042 for Luna, $0.0318 for Gemini and $0.0033 for Jev.

## Week 1 Day 3: Coding Agents & ADLC

- **Slides:** from vibe coding to working with coding agents. The landscape is IDEs like Cursor, extensions like GitHub Copilot and terminal agents like Claude Code, Codex and OpenCode, and a coding agent is a harness around a model, such as Claude Code around Claude Opus 5.5. OpenCode with OpenCode Zen's free models is the free route.
- **Slides:** "be the boss": the student owns what ships. AGENTS.md with progressive disclosure, permission modes (Ed uses auto), a fresh context for each task, a plan in phases with success criteria and frequent commits. Then MCP, with the Playwright server so the coding agent can test in a browser.
- **Slides:** the ADLC's second meaning, building code with agents, as Harness, Harden and Humans. The repo's controls are ruff, pyright, ESLint, strict TypeScript, pytest and vitest at 80% coverage, Playwright, a lefthook pre-commit hook and `npm run check`. Humans keep accountability, evaluations, judgment, taste and the harness.
- **Build:** the pilot from `docs/SPEC.md`, with no notebook today. "Please plan the pilot" writes `docs/PLAN.md` in six phases, then "Please implement the plan for the pilot". It builds a FastAPI and SQLite backend, a React dashboard with the queue, claim pages and the agent's steps, and a LangChain agent whose tools call the API. Ed runs Claude Code on Opus 5.5 at extra high effort, and it took 32 minutes.
- **Commands:** `npm install`, then `npm run dev` (the dashboard is at localhost:5173). `uv run -m agent` works the queue, `uv run -m backend.seed` resets it and `npm run check` runs every check. The Playwright MCP command for each coding agent is in `setup/INSTRUCTIONS.md`.
- **Watch out for:** free coding models need one small change at a time, with `npm run check` and a commit after each, and a second or third try. Ed makes a branch for the build, `week1day3-yourname`. To publish the build, push that branch: the sharing slide's `git push fork main` should name it.
- **Corrections:** MCP is the Model Context Protocol, where Ed says "Control". An MCP server added without a scope is local, for this user in this project only; `--scope user` covers all their projects and `-s project` shares it with the team. The commit hook runs the Python or TypeScript checks for the files being committed, and Playwright runs only in `npm run check`. Claude Code was a research preview in February 2025 and generally available in May 2025, where Ed says April.
- **Assignment:** share the pilot as `community_contributions/<name>/PILOT.md` with what they did, their takeaways and a link to their repo (see `guides/for_agents/AGENT_GIT_GUIDE.md`), and post about it on LinkedIn.

## Week 1 Day 4: Open-Source, Local, Token Cost

- **Slides:** proprietary, open-weight and open-source models. Open weights are mostly about privacy and control, and aren't necessarily cheaper. Then dense and mixture of experts models and active parameters, quantization (8-bit costs little, 4-bit starts to show), QAT, the file formats (safetensors, GGUF, MLX) and how to read a model's name.
- **Slides:** running models yourself with Ollama, LM Studio, llama.cpp and vLLM; what fits on a machine, and why memory bandwidth sets the speed; four ways to host an inference server, including renting a GPU on Runpod. OpenRouter's providers differ in precision, features and price, and you can pin them. Token pricing covers input, cached input, output and reasoning tokens, with the cost per claim.
- **Lab** (`week1day4`): a much shorter prompt on the 20 claims that don't need the manual. Six open-weight models on OpenRouter and three local ones on Ollama, plus optional Qwen 3.8 27B on Cerebras, compared on accuracy, cost and time, with charts of the Pareto frontier. `week1day4free` uses `openrouter/free`, and `week1day4cpu` has smaller local models for a computer without a GPU.
- **No product build:** the pilot is set aside today. Moving the product to a local model is a stretch assignment. The product only calls models through OpenRouter, so it needs a base URL setting first.
- **Watch out for:** Ollama is optional, and Gemma 4 E4B needs 16 GB of memory. Approving every claim gets 60% of decisions right, which compares with the decision score, not the stricter one. Cerebras needs its own account and `CEREBRAS_API_KEY`; to skip it, follow the notebook and take all three Cerebras results out of the list in Part 4. Results move between runs.
- **Corrections:** Amazon Bedrock runs the models in AWS's own accounts and doesn't forward calls to Anthropic. OpenRouter's routing with your own key (BYOK) is free up to a monthly allowance, then costs 5%. "Progressive profiling" should be progressive disclosure. `TINY = True` runs four claims, not five.

## Week 1 Day 5: Harness Engineering

- **Slides:** the move from prompt engineering to context engineering to harness engineering ("Agent = Model + Harness"), and the parts of a harness: context, workflow, state, subagents, permissions, observability and self-improvement. The student is a harness user with their coding agent and a harness builder with the UnderCover Agent, the course's focus. Build or buy is a spectrum: direct calls, LangChain's `create_agent`, Deep Agents and the Claude Agent SDK.
- **Labs:** two harnesses get the same job. A "claims desk" folder has five claims and no tools written for it, and the agent decides each claim through a subagent and leaves a handover note. Lab 1 uses the Claude Agent SDK on Claude Sonnet 5.5, costs about 40 cents and needs `ANTHROPIC_API_KEY`; students without one watch it. Lab 2 uses Deep Agents on DeepSeek V4.1 Flash for a few cents, and `week1day5_lab2free` works three claims on a free model.
- **Build** (HARNESS): the product's own harness on `create_agent`. A queue agent keeps a to-do list shown on the dashboard, a `work_claim` helper works each claim in a fresh context and reports in one line, and tools search and read sections of the policy wording and claims manual. A failed claim goes back in the queue, and a second failure leaves it for a handler. `uv run -m agent --cap 5` works five claims.
- **Watch out for:** the build passed every test, but Ed's review found messy code and prompts that spelled out every step instead of a goal, so a refactor followed. His notes are `docs/HUMAN_REVIEW_HARNESS.md` on `week1day5-end`, and `docs/PROCESS.md` there adds a review by a fresh subagent before each commit. Keep a referral, `left_for_handler` (two failed attempts) and `waiting_for_sign_off` apart.
- **Corrections:** in Lab 2, `recursion_limit=200` limits the graph's steps, not its messages. Working five of the 20 waiting claims leaves 15, where Ed says five. The slide's run command is a placeholder for `uv run -m agent --cap 5`. Anthropic's keys are now at platform.claude.com/settings/keys.
